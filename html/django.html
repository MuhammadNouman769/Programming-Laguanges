Introduction

What is Django?

🌐 Django in Simple Words

Django is a high-level Python web framework that enables rapid development of secure and maintainable websites. Built by experienced developers, it takes care of much of the hassle of web development, so you can focus on writing your app without needing to reinvent the wheel.

Django follows the "batteries-included" philosophy — it comes with everything you need to build a web application right out of the box. It handles authentication, database access, URL routing, and much more.

⚡ Fast Development

Django lets you build web applications extremely quickly, thanks to its built-in features and the "Don't Repeat Yourself" (DRY) principle.

🔒 Secure by Default

Django helps developers avoid many common security mistakes by providing built-in protection against CSRF, XSS, SQL injection, and clickjacking.

🏗️ How Does Django Work?

Django follows the MVT (Model-View-Template) architectural pattern, which is similar to MVC but with Django's own twist.

📐 MVT Pattern Explained

Handles data and business logic. Works with the database.

👁️

Chapter 01

Django Installation

Installing Django

Django is a Python package, so you install it using pip.

# Install Django pip install django # Check installation django-admin --version # Create a virtual environment (recommended) python -m venv myenv source myenv/bin/activate # On Windows: myenv\Scripts\activate pip install django
⚠️
Important Always use a virtual environment for your Django projects to keep dependencies isolated.

Creating Your First Django Project

# Create a new project django-admin startproject myproject # Navigate into the project cd myproject # Run the development server python manage.py runserver

Open your browser and go to http://127.0.0.1:8000 — you should see the Django welcome page!

Chapter 03

Django Apps

What is an App?

In Django, an app is a self-contained module that handles a specific functionality. A project can have many apps. Think of a project as a website (e.g., an e-commerce site), and apps as different features (e.g., products, cart, payments, user profiles).

# Create a new app python manage.py startapp myapp # Register the app in settings.py # Add 'myapp' to INSTALLED_APPS
💡
App Structure: Each app has its own models.py, views.py, urls.py, admin.py, and templates/ folder.
Chapter 04

Views & URLs

Creating a View

A view is a Python function (or class) that takes a request and returns a response.

# views.py from django.http import HttpResponse def home(request): return HttpResponse("Hello, World!")

Mapping URLs

# urls.py (project-level) from django.urls import path from myapp import views urlpatterns = [ path('', views.home, name='home'), ]

Function-Based Views (FBV)

Simple and straightforward — just a Python function.

def my_view(request): return render(request, 'template.html')

Class-Based Views (CBV)

More structured and reusable — extend Django's built-in views.

from django.views.generic import TemplateView class MyView(TemplateView): template_name = 'template.html'
Chapter 05

Templates

Django Template Language

Django's template language is designed to be simple and readable. It uses special tags and filters to render dynamic content.

{# templates/index.html #} <!DOCTYPE html> <html> <head> <title>{{ title }}</title> </head> <body> <h1>Welcome, {{ user.name }}!</h1> {# Loop through data #} <ul> {% for item in items %} <li>{{ item.name }} - {{ item.price }}</li> {% endfor %} </ul> {# Conditional rendering #} {% if user.is_admin %} <p>Admin privileges available.</p> {% endif %} {# Template inheritance #} {% extends "base.html" %} {% block content %} <p>This is the content.</p> {% endblock content %} </body> </html>

Common Template Tags

TagPurpose
{% for %}Loop over items
{% if %}Conditional rendering
{% url %}Generate URLs by name
{% include %}Include another template
{% extends %}Inherit from a parent template
{% block %}Define a block in a template

Models

Defining Models

Models are Python classes that define the structure of your database tables. Each model maps to a single database table.

# models.py from django.db import models class BlogPost(models.Model): title = models.CharField(max_length=200) content = models.TextField() published_at = models.DateTimeField(auto_now_add=True) author = models.CharField(max_length=100) def __str__(self): return self.title
CharFieldText with limited length
TextFieldUnlimited text
IntegerFieldWhole numbers
DateTimeFieldDate and time
BooleanFieldTrue/False
ForeignKeyOne-to-many relationship

Model Relationships

# One-to-Many (Foreign Key) class Comment(models.Model): post = models.ForeignKey(BlogPost, on_delete=models.CASCADE) text = models.TextField() created_at = models.DateTimeField(auto_now_add=True) # Many-to-Many class Post(models.Model): tags = models.ManyToManyField('Tag') # One-to-One class UserProfile(models.Model): user = models.OneToOneField(User, on_delete=models.CASCADE) bio = models.TextField()
Chapter 07

Django ORM

Querying the Database

The Django ORM (Object-Relational Mapper) lets you interact with the database using Python code instead of SQL.

# Get all objects posts = BlogPost.objects.all() # Filter posts = BlogPost.objects.filter(author="Akarsh") posts = BlogPost.objects.filter(published_at__year=2024) # Get a single object post = BlogPost.objects.get(id=1) # Ordering posts = BlogPost.objects.order_by('-published_at') # descending # Chaining posts = BlogPost.objects.filter(author="Akarsh").order_by('-published_at') # Creating post = BlogPost.objects.create(title="New Post", content="...", author="Akarsh") # Updating post.title = "Updated Title" post.save() # Deleting post.delete()

Chapter 08

Migrations

What are Migrations?

Migrations are Django's way of propagating changes you make to your models into your database schema. They're like version control for your database.

# Create migrations for changes in models python manage.py makemigrations # Apply migrations to the database python manage.py migrate # See the SQL that will be executed python manage.py sqlmigrate myapp 0001 # Check for any unapplied migrations python manage.py showmigrations
⚠️
Important Always run makemigrations after changing your models, then migrate to apply the changes to your database.
Chapter 09

Admin Panel

Django's Built-in Admin

Django provides a fully-featured admin interface out of the box. You can register your models and get a complete CRUD interface for free.

# admin.py from django.contrib import admin from .models import BlogPost class BlogPostAdmin(admin.ModelAdmin): list_display = ['title', 'author', 'published_at'] list_filter = ['author', 'published_at'] search_fields = ['title', 'content'] ordering = ['-published_at'] admin.site.register(BlogPost, BlogPostAdmin)
🔑
Create a superuser: python manage.py createsuperuser — then visit /admin in your browser.

Forms

Django Forms

Django has a built-in form system that handles validation, rendering, and CSRF protection.

# forms.py from django import forms from .models import BlogPost class BlogPostForm(forms.ModelForm): class Meta: model = BlogPost fields = ['title', 'content', 'author'] widgets = { 'content': forms.Textarea(attrs={'rows': 10}), }
# views.py def create_post(request): if request.method == 'POST': form = BlogPostForm(request.POST) if form.is_valid(): form.save() return redirect('home') else: form = BlogPostForm() return render(request, 'create.html', {'form': form})
{# create.html #} <form method="POST"> {% csrf_token %} {{ form.as_p }} <button type="submit">Submit</button> </form>
Chapter 11

Django Authentication

Built-in Authentication

Django comes with a complete authentication system including user registration, login, logout, password reset, and more.

# urls.py from django.contrib.auth import views as auth_views urlpatterns = [ path('login/', auth_views.LoginView.as_view(), name='login'), path('logout/', auth_views.LogoutView.as_view(), name='logout'), path('signup/', views.signup, name='signup'), ]
# views.py from django.contrib.auth.forms import UserCreationForm from django.contrib.auth import login def signup(request): if request.method == 'POST': form = UserCreationForm(request.POST) if form.is_valid(): user = form.save() login(request, user) return redirect('home') else: form = UserCreationForm() return render(request, 'signup.html', {'form': form})
🔒
Protecting views: Use @login_required decorator to restrict access to authenticated users only.

Class-Based Views

Common Built-in CBVs

Class-Based Views (CBVs) provide reusable view logic in an object-oriented way.

from django.views.generic import ListView, DetailView, CreateView, UpdateView, DeleteView from django.contrib.auth.mixins import LoginRequiredMixin from .models import BlogPost class PostListView(ListView): model = BlogPost template_name = 'posts/list.html' context_object_name = 'posts' ordering = ['-published_at'] paginate_by = 10 class PostDetailView(DetailView): model = BlogPost template_name = 'posts/detail.html' class PostCreateView(LoginRequiredMixin, CreateView): model = BlogPost fields = ['title', 'content'] template_name = 'posts/create.html' success_url = '/' def form_valid(self, form): form.instance.author = self.request.user return super().form_valid(form)
Chapter 13

Django Middleware

What is Middleware?

Middleware sits between the request and response. It's a way to process every request/response globally — useful for authentication, logging, and security.

# middleware.py class RequestLoggingMiddleware: def __init__(self, get_response): self.get_response = get_response def __call__(self, request): # Runs before the view print(f"Request: {request.method} {request.path}") response = self.get_response(request) # Runs after the view print(f"Response: {response.status_code}") return response
⚙️
Registering middleware: Add your middleware to the MIDDLEWARE list in settings.py.

Static Files

Handling Static Files

Static files include CSS, JavaScript, images, and other assets. Django handles them differently in development and production.

# settings.py STATIC_URL = '/static/' STATICFILES_DIRS = [ BASE_DIR / "static", ] STATIC_ROOT = BASE_DIR / "staticfiles" # For production
{# In templates #} {% load static %} <link rel="stylesheet" href="{% static 'css/style.css' %}"> <img src="{% static 'images/logo.png' %}" alt="Logo"> # Collect static files for production python manage.py collectstatic

Django REST Framework

Building APIs with DRF

Django REST Framework (DRF) is a powerful toolkit for building Web APIs in Django.

# Install DRF pip install djangorestframework # serializers.py from rest_framework import serializers from .models import BlogPost class BlogPostSerializer(serializers.ModelSerializer): class Meta: model = BlogPost fields = ['id', 'title', 'content', 'author', 'published_at']
# views.py (API) from rest_framework import generics from .models import BlogPost from .serializers import BlogPostSerializer class PostListAPI(generics.ListCreateAPIView): queryset = BlogPost.objects.all() serializer_class = BlogPostSerializer # urls.py (API) urlpatterns = [ path('api/posts/', PostListAPI.as_view(), name='api_posts'), ]

Deployment

Preparing for Production

Deploying a Django application involves several steps to ensure security and performance.

⚠️
Critical Settings Changes:
• DEBUG = False
• ALLOWED_HOSTS = ['yourdomain.com']
• Use environment variables for secret keys
• Set up a proper database (PostgreSQL recommended)
# settings.py for production import os from django.core.management.utils import get_random_secret_key SECRET_KEY = os.getenv('DJANGO_SECRET_KEY', get_random_secret_key()) DEBUG = os.getenv('DEBUG', 'False') == 'True' ALLOWED_HOSTS = os.getenv('ALLOWED_HOSTS', 'localhost').split(',')
# Using Gunicorn + Nginx # Install Gunicorn pip install gunicorn # Run with Gunicorn gunicorn --workers 4 myproject.wsgi:application # For static files in production python manage.py collectstatic
